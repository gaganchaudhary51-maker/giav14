# GIA UNIVERSAL AI — MASTER BLUEPRINT
## V14 LOCKED CANONICAL BASELINE
**Status:** LOCKED

GIA is the Universal AI Commander. Specialist agents are internal workers.

### Product contract
One coherent system for natural text/voice conversation, dynamic agent workforce, software building, repository engineering, governed tools, testing/diagnosis/repair, checkpoints/rollback, project memory/RAG, multi-LLM routing and responsive desktop/mobile UX.

### V14 builder baseline
Authenticated CRUD SaaS: React + TypeScript frontend, FastAPI backend, MongoDB-compatible data architecture, authentication, authorization, roles, permissions, dashboard, CRUD APIs/forms, validation, responsive UI, tests, checkpoints and rollback.

### Workforce
Dynamic specialists: planning/product, architecture, frontend, backend, database, AI/ML, automation, UI/UX, research/RAG, business/analytics, QA/debugging, security and DevOps/deployment.

### Execution
REQUESTED → PLANNED → APPROVAL_REQUIRED (if required) → APPROVED → EXECUTING → EXECUTED → VERIFYING → VERIFIED → RELEASED.
Failures: FAILED → DIAGNOSING → REPAIRING → RETESTING → ROLLED_BACK.

### Governance
Sensitive actions require human approval. Projects are tenant-isolated. Tools have scoped permissions, timeouts, resource/network restrictions and audit records. Secrets never enter generated frontend code.

### Model/credit policy
Deterministic tools first. Cheap/fast models for routine work; escalation for complex coding, architecture, security and repeated failures. Use targeted context retrieval and budgets.

### Voice
Voice is an interface to GIA. Browser STT/TTS fallback and pluggable providers are allowed. No unlimited-free claim.

### Memory/RAG
Project-scoped and tenant-isolated. May index source files, requirements, documents, decisions, tests and deployment notes.

### Truthfulness
PLANNED, GENERATED, EXECUTED, TESTED, VERIFIED and DEPLOYED are distinct. VERIFIED requires evidence. No fake tests, terminal output, database operations, deployment or integrations.

### Engineering discipline
Inspect before editing. Prefer minimal diffs. Preserve working functionality. Do not silently replace the architecture.

### Acceptance target
A real Customer CRM must be buildable and modifiable through GIA with auth, roles, CRUD, API/data layer, responsive UI, tests, governed execution, checkpoint/rollback and diagnosis/repair evidence.
